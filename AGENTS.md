## Ikwe messaging rules

Ikwe is the independent behavioral safety layer for human-facing AI.

### Canonical naming hierarchy
- Behavioral Safety Validation = category
- EQ Safety Benchmark = framework
- Frontier AI Behavioral Safety Index = public benchmark leaderboard
- Ikwe EQ Safety Evaluation = private client evaluation service
- Ikwe Behavioral Monitoring = ongoing governance monitoring layer

### Product architecture
1. EQ Safety Benchmark
- behavioral evaluation framework
- binary Safety Gate
- 8 weighted behavioral dimensions
- can evaluate any AI response in emotionally sensitive contexts

2. Public Benchmark Audit
- baseline 79 real-world emotional support scenarios
- scenarios sourced from established datasets
- used to continuously evaluate frontier models publicly
- published publicly as the Frontier AI Behavioral Safety Index

3. Private Client Evaluation + Monitoring
- private client benchmark evaluations via Ikwe EQ Safety Evaluation
- optional client-specific scenarios
- live system output / API monitoring via Ikwe Behavioral Monitoring
- drift detection over time

### Messaging rules
- Do not describe the benchmark as the 79-scenario set.
- Do not describe the scenarios as simulated.
- Prefer: “real-world behavioral risk scenarios sourced from established datasets.”
- Prefer: “human-facing AI” for category positioning.
- Use “vulnerable users” or “emotionally sensitive contexts” for risk framing.
- Keep “independent validation” prominent in major positioning sections.
- Write in short, declarative, enterprise-facing sentences.
- When messaging changes, update this file in the same pass so naming stays consistent across homepage, benchmark, research, audit, intake, and supporting materials.
